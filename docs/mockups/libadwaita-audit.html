Fedora Updater against libadwaita 1.10

Audit of the current GTK 4 / libadwaita UI (src/ui/window.blp, src/ui/log_window.blp, src/ui/rows.rs, src/style.css) against the libadwaita 1.10 widget and style guidance and the GNOME HIG patterns those docs point at. The crate is libadwaita 0.8 with the v1_7 feature. Findings below are deviations, not a rewrite of the update flow. Each section shows the app today (Current), the audit suggestion (Proposed), and the accepted picture (Final).

Already in line with the kit

  • AdwApplicationWindow, AdwToolbarView, AdwHeaderBar, and AdwToastOverlay are the right shells. Color scheme follows the system.
  • Idle, authentication, and failure use AdwStatusPage. The idle primary button is a single suggested pill.
  • Confirmations use AdwAlertDialog, not the deprecated message dialog. Stop defaults to “keep waiting”, marks “stop” destructive, and Esc cancels.
  • Package lists are AdwPreferencesGroup plus AdwActionRow inside AdwClamp. Completed rows use AdwExpanderRow. Soft errors and a stalled run use AdwBanner. Spinners use AdwSpinner.
  • Toasts cover reboot and internal errors, which is the right weight for those events.

Final is the picture to implement. Proposed stays so the earlier suggestion is still visible. The link opens that section.

12. Stylesheet

.dim-label is deprecated since 1.7. .dimmed is the replacement, and the crate already enables v1_7. The blueprint and rows.rs still apply dim-label. High contrast asks for style classes and CSS variables instead of fixed opacity and handmade borders. src/style.css sets .pkg-row.pending { opacity: 0.72 }, borders with alpha(@window_fg_color, 0.14), and Flatpak and enhancement text to @purple_1. In libadwaita 1.10 that named color is #dc8add, and it does not change between light and dark. Against white that is about 2.4:1, short of 4.5:1. On the dark window it is about 6.6:1, so the miss is the light style and high contrast, which will not darken this palette stop. The clamp example uses 12px side margins and 24px between groups. The pages use 16px. .stage-apply repaints the progress bar with @success_bg_color even though the caption already names the pass.
